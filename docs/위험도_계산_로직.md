# DB-care 위험도 계산 로직 — 낱낱이 정리 (v2.2.2)

> "이 화면의 이 숫자는 어디서 어떻게 나왔나"를 페이지별·요소별로 정리한 문서.
> 모든 공식은 실제 코드 기준 (backend/ml/predictor.py, backend/routers/scenario.py,
> backend/services/derived.py, backend/services/percentile.py, frontend/*).

---

## 0. 한눈에 — 위험도는 3가지 출처가 섞여 나온다

화면의 "위험도"는 단일 알고리즘이 아니라 **세 종류의 로직**이 합쳐진 결과다.

| 출처 | 무엇 | 어디에 쓰이나 |
|------|------|---------------|
| ① **ML 모델** | 6개 합병증 pkl (XGBoost/Stacking/EasyEnsemble/CatBoost) 예측 확률 | 합병증 카드 점수·등급, 라다, 시나리오 baseline |
| ② **임상 안전망 (clinical floor)** | HbA1c≥11 등 7가지 룰로 등급 강제 상향 | 합병증 등급(level) 보정 — ML이 놓치는 위험 방지 |
| ③ **수치 기반 휴리스틱** | 검사값을 정상범위와 비교 / 공식 계산 | 위험요인 패널, 검사 테이블 비고, 시나리오 수명·의료비 |

→ **"정상 수치인데 왜 위험?"** 같은 의문은 대부분 ②(안전망) 또는 신규 3개 저AUC 모델 때문.
→ **"이 숫자(수명/의료비/배수)는 ML이 아니라 ③(공식)"** 인 경우가 많다.

## 1. 핵심 개념 (모든 페이지 공통)

### 1.1 점수(score) 3종 — 헷갈리면 안 됨

| 필드 | 의미 | 계산 |
|------|------|------|
| `raw_score` / `score` | ML 모델 원본 예측 확률 × 100 (0~100) | `predict_proba × 100` |
| `display_score` | **화면 진행바/게이지용** 점수 | floor로 등급 승격 시 밴드 하한까지 끌어올린 값 |
| `level` | 등급 (저위험/중위험/고위험) | 아래 1.2 |

**왜 display_score가 따로 있나 (v2.2.2 H1)**: HbA1c 13.9%로 안전망이 "고위험" 등급을 강제해도
ML raw_score는 낮을 수 있다(예: 2점). 그러면 "고위험 배지 + 1/100 짜리 짧은 바"라는 모순이
생긴다. `display_score`는 등급에 맞춰 바 길이를 보정한 값이고, **raw_score는 ML 원본 그대로 보존**된다.
- 고위험: `display_score = max(score, 60, threshold)`
- 중위험: `display_score = min(max(score, threshold), 59.9)`
- 저위험: `display_score = score` (변경 없음)
- 코드: `predictor.py :: _floor_band_score()`, `predict_all()` 말미

### 1.2 등급 분류 `_classify_risk` (단일 진실 소스)

ML 점수(score)를 **모델별 학습 threshold** 기준으로 등급화. (predictor.py:447)

```
threshold 있을 때:
  고위험 = score ≥ 60  AND  score ≥ threshold
  중위험 = score ≥ threshold        (고위험 아님)
  저위험 = score < threshold
threshold 없을 때(구모델/더미): 60/30 고정 fallback
```

- `threshold`는 각 pkl이 학습 때 정한 "양성/주의" 컷오프 (Youden's J / F-beta로 선정).
- 예: 망막병증 threshold ≈ 19.5 → score 25면 **중위험** (60 미만이라 고위험은 아님).
- **단일 소스**: `classify_disease_risk(score, disease, age)` — 백엔드·프론트·시나리오 모두 이걸 통해 등급화.
  프론트가 자체 30/60을 쓰면 모델 threshold와 어긋나므로 항상 backend `level`을 우선 사용.

### 1.3 임상 안전망 `apply_clinical_floor` — 7룰 (predictor.py:579)

ML이 저평가해도 **임상적으로 명백한 고위험을 놓치지 않도록** 등급을 강제 상향.
**점수(score)는 절대 안 바꾸고 등급(level)만 올린다.** 사유는 `clinical_flags`에 기록.

| 룰 | 조건 | 효과 |
|----|------|------|
| 1 | HbA1c ≥ 11% | **모든 합병증 무조건 고위험** |
| 2 | HbA1c ≥ 9% | 모든 합병증 최소 중위험 |
| 3 | C-peptide < 0.5 | 최소 중위험 (1형 의심) |
| 4 | DM 유병 ≥ 10년 AND HbA1c ≥ 8.5 | 최소 중위험 (누적 위험) |
| 5 | eGFR < 45 OR UACR ≥ 300 | **무조건 고위험** (신증 3기↑) |
| 6 | SBP ≥ 160 OR DBP ≥ 100 | 최소 중위험 (중증 고혈압) |
| 7 | LDL ≥ 190 | 최소 중위험 (가족성 고지혈 수준) |

- 원칙: **등급은 올리기만, 절대 내리지 않음** (downgrade 금지).
- 별도 신호(등급과 분리): C-peptide 3단계 미세혈관 flag, HOMA-IR 4분위(≥1.69) 대혈관 flag.
- ⚠️ 현재 한계: Rule 5의 `UACR`는 병원 입력 스키마에 없어 사실상 eGFR<45 부분만 발동.

### 1.4 모델 현황 (`model_role`)

| 합병증 | 모델 | val AUC | role |
|--------|------|---------|------|
| 신장질환 kidney | Stacking(XGB+LGB+CB→LR) | 0.752 | `clinical` |
| 망막병증 retina | XGBoost | 0.843 | `clinical` |
| 심혈관 cardio | EasyEnsemble | 0.761 | `clinical` |
| 신경병증 neuro | CatBoost | 0.61~ | **`screening`** |
| 치매 dementia | Calibrated CatBoost | ~0.73 | **`screening`** |
| 뇌혈관 cerebro | CatBoost | ~0.70 | **`screening`** |

- 신규 3개는 저AUC라 화면에 **"선별" 배지 + "임상 확인 필요"** 표시 (v2.2.2 H4).
  정상 환자가 이 모델만으로 중위험이 뜰 수 있음 → 배지로 신뢰수준을 명시.

### 1.5 나이 정규화 (v2.2.2 H3)

- 저장된 `age`는 검사일(exam_date) 시점 나이라 시간이 지나면 화면 표시(현재 만나이)와 어긋난다.
- `predict_all` 진입부 `_normalize_age_duration()`에서 **dob 기준 현재 만나이**로 1회 정규화 →
  features / 안전망 / percentile 전부 동일 나이 사용. (이전엔 features는 현재나이, floor는 저장나이라 불일치)
- dm_duration = 현재나이 − 진단나이 (음수 방지).

### 1.6 파생값 자동 계산 (derived.py — 병원 원본값 → 모델 입력값)

병원은 원본 측정값만 입력하고, 다음은 백엔드가 계산해 DB에 저장(업로드/POST/PATCH 동일 경로):

| 파생값 | 공식 |
|--------|------|
| 만나이 age | dob + exam_date |
| BMI | `weight / (height/100)²` |
| LDL | 실측 우선, 없으면 Friedewald `chol − HDL − TG/5` (TG<400, **음수면 미산출**) |
| non-HDL | `chol − HDL` (**음수면 미산출**, v2.2.2 M8) |
| eGFR | CKD-EPI 2009 (Cr, age, sex) |
| HOMA-IR | `공복혈당 × C-peptide / 405` |
| HOMA-β | `360 × C-peptide / (공복혈당 − 63)` |
| TyG index | `ln(TG × 공복혈당 / 2)` |
| BMI_HOMA_IR | `BMI × HOMA-IR` |
| 맥압(pulse pressure) | `SBP − DBP` (**SBP<DBP면 미산출**, v2.2.2 M8) |
| 당뇨 이환기간 | `현재나이 − 진단나이` |
| he_insulin | `C-peptide × 3.0` (구 UI 하위호환 저장용, 모델은 C-peptide 직접 사용) |

⚠️ v2.2.2 (H2): 환자 정보 PATCH(데이터 수정) 시에도 위 파생값을 **재계산**해 DB 컬럼 갱신
(이전엔 Cr 등 입력만 바뀌고 eGFR 등 표시값이 stale 됐음).

## 2. 페이지별 — 무엇이 ML이고 무엇이 수치 기반인가

### 2.1 Dashboard (환자 대시보드)

| 화면 요소 | 출처 | 계산 |
|-----------|------|------|
| **6개 합병증 카드 등급/바** | ① ML + ② 안전망 | `predict_all` → `level`(floor 반영), 바 = `display_score` |
| 카드의 "임상 주의 신호" 사유 | ② 안전망 | `clinical_flags`의 affects_level 메시지 (정상수치인데 위험인 이유) |
| 카드 "선별" 배지 | model_role | 신규 3개 저AUC 모델 표시 |
| **CRITICAL STATUS 반원 게이지** | ① + ② | 6개 중 최고위험 합병증의 `level` + `display_score` |
| 카드에 보이는 핵심 지표값 (eGFR/나이/SBP 등) | ③ **수치(원본값)** | 단순히 그 환자의 검사값 표시 (위험도 계산 아님) |
| **"주요 위험 요인 분석" 패널 (우측)** | ③ **수치 기반 (ML 아님!)** | 아래 ★ |
| C-peptide 추이 차트 | 원본 측정 이력 | measurements 시계열 |

★ **"주요 위험 요인 분석" 패널은 ML이 아니라 수치 기반 휴리스틱이다** (Dashboard.jsx:40, riskPct)
- 고정 7지표(C-peptide / HbA1c / 공복혈당 / SBP / BMI / eGFR / 나이)를 **정상범위 대비 이탈 정도**로 바 길이 정규화.
- 예) HbA1c: `≤ 7%면 (값/7)×40%, 초과면 ((값−7)/7)×200+40%` → 정상범위에서 얼마나 벗어났나.
- 예) eGFR: `≥120이면 10%, 60~120이면 30%, <60이면 (60−값)/60×100%` (낮을수록 위험).
- ⚠️ 이 패널은 **합병증별 실제 기여요인이 아니라 고정 지표 7개**다 (현재 한계, 후속 개선 대상 = F4).
  바 밑 설명: "바는 정상 범위 대비 이탈 정도를 나타냅니다".

### 2.2 PatientDetail (환자 상세)

| 화면 요소 | 출처 | 계산 |
|-----------|------|------|
| **AI 합병증 예측 카드** | ① ML + ② 안전망 | 위험지수 = `display_score`, 등급 = `level`, 사유 = affects_level flag, "선별" 배지 |
| **최근 검사 수치 테이블 비고(정상/주의/높음)** | ③ **수치 기반** | 각 항목을 정상범위와 비교 (아래) |
| 수치 추이 차트 (C-peptide/HbA1c/Cr) | 원본 측정 이력 | 시계열 |

검사 테이블 비고 판정(③ 수치 기반, CLAUDE.md 기준):
- 당화혈색소: ≤5.6 정상 / 5.7~6.4 주의 / ≥6.5 높음
- 공복혈당: ≤99 정상 / 100~125 주의 / ≥126 높음
- Cr: 0.6~1.2 정상 / 초과 높음 · GGT/ALT/AST: ≤기준 정상
- 총콜레스테롤: ≤199 / 200~239 주의 / ≥240 · BMI: ≤22.9 / 23~24.9 과체중 / ≥25 비만

### 2.3 RiskAnalysis (시나리오 분석) ★ 가장 복잡 — 로직 4겹

이 페이지는 **ML + 안전망 + 휴리스틱 + 고정값**이 모두 등장한다.

#### (A) 라다 차트 / 현재 위험 프로필
- `radar` = `predict_with_simulation(환자, 슬라이더 C-peptide, 슬라이더 HbA1c)`의 ML 점수.
  - 슬라이더가 입력으로 들어가 ML이 재예측 (슬라이더 HbA1c → 공복혈당도 `18 × HbA1c`로 함께 갱신).
  - 등급/색은 모델 threshold 기준 (`{score, display_score, level}` 객체로 전달, v2.2.2 R3).

#### (B) 슬라이더 변화량 → 시뮬레이션 강도 (scenario.py)
모든 시나리오 수치는 아래 두 축으로 결정:
```
baseline_sev = clamp( 평균(radar 점수) / 70 , 0.15 , 1.0 )      # 환자 현재 위험 severity
drift_worse  = max(0, 슬라이더HbA1c − 현재HbA1c) + max(0, 현재Cpep − 슬라이더Cpep)
drift_better = max(0, 현재HbA1c − 슬라이더HbA1c) + max(0, 슬라이더Cpep − 현재Cpep)
```

#### (C) 합병증 등급/점수 (3 시나리오)
| 시나리오 | 점수 계산 | 등급 |
|----------|-----------|------|
| 치료 방치 | `_worsen = clamp(radar + baseline_sev×8 + drift_worse×5, 1, 95)` | `max(재분류, 현재 안전망등급)` |
| 집중관리 | `_improve = clamp(radar − baseline_sev×6 − drift_better×8, 2, 90)` | `max(재분류, 개선수치 안전망 재평가)` |
| 졸업 | 표준 졸업값으로 `predict_all` 재예측 후, 집중관리×0.9 이하로 clamp | `max(재분류, 표준값 안전망)` |

- 방치/집중도 **안전망을 다시 적용**(v2.2.2 F2/H5): 예) 집중관리 후 HbA1c가 아직 ≥11이면 고위험 유지(과소표시 방지).
- 졸업도 잔존 안전망(eGFR<45 등 비가역) 존중.

#### (D) 예상 건강수명·의료비 (★ 수치/휴리스틱 — ML 아님)

**치료 방치:**
```
life_hit     = clamp(baseline_sev×12 + drift_worse×3, 0.5, 18)
방치 수명     = max(50, 나이+1, int(82 − 나이/10 − life_hit))
cost_base    = 80 + baseline_sev×350 + drift_worse×100
방치 의료비   = max(120, cost_base + baseline_sev×200)   (만원/년)
의료비 증가율 = clamp(baseline_sev×(15 + drift_worse×50), 5, 130) %
인슐린 확률   = clamp(baseline_sev×(15 + drift_worse×60), 2, 90) %
당뇨약 개수   = before(1~2) → before + clamp(baseline_sev×1.5 + drift_worse×1.5, 0, 4)
```

**졸업 (v2.2.2 — 고정, 슬라이더 영향 없음):**
```
졸업 수명   = max(62, 나이+5, int(82 − 나이/10 + 10))      # age만 의존
졸업 의료비 = clamp(40 + 나이×0.2, 40, 55)                 # age만 의존
```
→ **슬라이더를 움직여도 졸업 박스 수명·의료비는 안 변한다** (완전 회복 = 고정 최선값).

**집중관리 (v2.2.2 — 졸업 수렴):**
```
집중 수명(휴리스틱) = max(60, 나이+3, 방치수명+2, int(82 − 나이/10 + life_gain))
  life_gain = clamp(baseline_sev×5 + drift_better×3, 1, 8)
집중 의료비(휴리스틱) = clamp(cost_base×0.4, 60, 400)

# 졸업 수렴 보정:
managed_gap = |슬라이더HbA1c−5.6|×0.7 + |슬라이더Cpep−1.3|×0.4
            + max(0,SBP−130)×0.04 + max(0,DBP−85)×0.04
            + max(0,BMI−25)×0.06 + max(0,18.5−BMI)×0.04
grad_conv   = clamp(1 − managed_gap/2, 0, 1)              # 0=먼 상태, 1=졸업 수렴

집중 수명   = 휴리스틱 + (졸업수명 − 휴리스틱) × grad_conv
집중 의료비 = 휴리스틱 + (졸업의료비 − 휴리스틱) × grad_conv
```
→ **슬라이더를 졸업값(5.6/1.3)에 맞추고 환자 동반수치(혈압·BMI)도 정상이면 집중 = 졸업** (수렴).
→ 혈압·BMI가 졸업 기준과 다르면 그만큼 격차 유지.
→ 보간 범위가 `[휴리스틱, 졸업]` 안이라 **항상 방치 < 집중 < 졸업** (단조성) 보존.

#### (E) "같은 나이대 대비 X배" (방치 카드, percentile.py)
- ③ **코호트 비교** (ML 점수를 KNHANES 동일 연령대와 비교).
- `fold = 환자 ML점수 / 동일 연령대 코호트 중앙값` (knhanes_percentiles.json).
  - fold > 1.0 = 평균보다 위험 높음, < 1.0 = 낮음.
- Dashboard 카드의 "위험도 상위 X%"도 같은 데이터(percentile)로 산출.

#### (F) 전조증상 / 회복 메시지
- 방치: 합병증 worsened **등급**에 따라 SYMPTOM_BANK에서 HIGH/MEDIUM/LOW 증상 노출 (수치 아님, 등급 기반 사전).
- 집중: 방치 측 증상에 1:1 대응하는 회복 한 줄.

### 2.4 CaseComparison (유사 사례)
- 현재 **더미 데이터** (CLAUDE.md 명시). 유사도 상위 3건, 의료비 절감/건강수명은 예시값.
- ⚠️ 실제 개선 이력 없이도 절감액이 표시될 수 있음 (후속 개선 대상).

## 3. "이 숫자 어디서 나왔나" 빠른 색인

| 화면의 숫자 | 출처 | 핵심 공식 |
|-------------|------|-----------|
| 합병증 위험지수 (XX/100) | ML + 안전망 | `display_score` (raw=ML, floor 승격 시 밴드 보정) |
| 합병증 등급 (저/중/고) | ML threshold + 안전망 | `_classify_risk` + 7룰 floor |
| "정상수치인데 고위험" 이유 | 안전망 | `clinical_flags` (예: HbA1c≥11) |
| 위험요인 패널 바 | **수치(정상범위 이탈)** | `riskPct(값, 정상범위)` — ML 아님 |
| 검사 비고(정상/주의/높음) | **수치(정상범위)** | 항목별 컷오프 |
| 라다 축 길이 | ML(슬라이더 반영) | `predict_with_simulation` |
| 방치/집중 수명·의료비 | **휴리스틱** | baseline_sev + drift 공식 (위 2.3 D) |
| 졸업 수명·의료비 | **고정 공식(age)** | `max(62,age+5,82−age/10+10)` / `clamp(40+age×0.2,40,55)` |
| 집중→졸업 수렴 | 휴리스틱+보간 | `휴리스틱 + (졸업−휴리스틱)×grad_conv` |
| "같은 나이대 대비 X배" | **코호트 비교** | `ML점수 / 코호트 중앙값` |
| "위험도 상위 X%" | **코호트 percentile** | knhanes_percentiles.json |
| eGFR/BMI/LDL/HOMA 등 | **공식 계산** | derived.py (위 1.6) |

## 4. 자주 묻는 의문 (의료진 관점)

**Q. eGFR 108(정상)인데 신장질환 고위험?**
A. ML 점수는 낮아도 HbA1c≥11 등 안전망(Rule 1)이 모든 합병증을 고위험으로 강제. 카드 사유에
   "HbA1c 13.9% — 무조건 고위험 안전망"이 표시됨. 카드가 보여주는 eGFR는 위험 계산 근거가 아니라 참고 지표.

**Q. SBP 127(정상)인데 심혈관 중위험?**
A. (a) 안전망(HbA1c 등) 또는 (b) 심혈관 ML 모델 자체 판단. 신규 3개(신경/치매/뇌혈관)는 저AUC라
   "선별" 배지로 신뢰수준을 명시.

**Q. 슬라이더를 졸업값에 맞췄는데 집중관리가 졸업과 다르다?**
A. 졸업은 6개 값(+혈압 120/80, BMI 22, 공복혈당 90)을 모두 정상화하지만 슬라이더는 2개(HbA1c·C-peptide)만
   바꾼다. 환자의 실제 혈압/BMI가 졸업 기준과 다르면 managed_gap만큼 격차가 남는다. 동반수치까지 정상이면 수렴.

**Q. 위험요인 패널이 환자마다 같은 7개다?**
A. 맞다. 현재는 합병증별 기여요인이 아니라 고정 7지표의 정상범위 이탈 표시 (후속 개선 대상 F4).
