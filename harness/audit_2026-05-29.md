## 종합 판정

> **현재 코드만으로 "그대로 병원 배포 OK"는 아님 — 조건부 가능.**
> codex 양쪽 독립 감사 모두 동일 결론.

두 축이 핵심:
1. **환자 안전 (의료 정확성)** — 모델 실패/결측/룰 실패가 전부 "정상 점수"로 보이는 구조 (Critical)
2. **PHI 보안** — 환자 개인정보 평문 저장 (High)

배포 조건: 단일 전용 PC + 디스크 암호화(BitLocker/FileVault) + OS 계정 분리를 병원 정책으로 강제하면 보안 측면은 조건부 충족. 단 의료 정확성(Critical)은 코드 수정 없이는 미해결.

## 🔴 Critical — 환자 안전 직결

### C1. 모델 로드/예측 실패 시 더미값을 정상 예측처럼 표시
- **위치**: `backend/ml/predictor.py:759-784`, `863-865`, `908-910`
- **내용**: pkl 누락/전처리 실패 시 `random.uniform(15,85)` 더미 점수를 `available=True`로 반환. v2.1.8에서 `risk_source="fallback_dummy"` 구분은 추가했으나 UI는 여전히 정상 카드로 표시.
- **위험**: 모델이 깨져도 의사는 "정상 예측"으로 신뢰 → 오진.
- **수정안**: 더미 대신 `available=False` + HTTP 503, UI는 "예측 불가" 명시.

### C2. 결측 검사수치를 "평균 당뇨환자" 기본값으로 대체
- **위치**: `backend/ml/predictor.py:270-288` (직접 확인)
- **내용**: 결측 시 FBG 126 / HbA1c 7.0 / Cr 1.0 / C-peptide 2.7 / BMI 25 / SBP 130 등 임상 기본값 주입 후 예측.
- **위험**: 검사 안 한 환자가 그럴듯한 가짜 위험도를 받음. imputer가 처리해야 할 결측을 그 전에 가려버림.
- **수정안**: 기본값 대체 최소화, imputer에 NaN 전달해 학습된 결측 처리 경로 사용.

## 🟠 High

### H1. 환자 PHI 평문 저장
- **위치**: `database.py:32-40,75-83`, `services/export_csv.py:36-58,82-142`, `patients.py:210-216`
- **내용**: SQLite DB + `.premigrate.bak` + CSV 미러/백업 모두 이름·차트번호·전화·검사수치 평문.
- **수정안**: SQLCipher 또는 OS 계정+디스크 암호화 강제. CSV 미러 기본 OFF, export 폴더 ACL/보존기간/삭제 기능.

### H2. 임상 안전망 실패를 broad except로 삼킴
- **위치**: `backend/ml/predictor.py:957-966`
- **내용**: cpep flag/clinical floor 계산 실패 시 경고만 출력, 예측은 성공 처리.
- **위험**: HbA1c≥11 같은 안전망 룰이 조용히 누락된 채 낮은 위험도 표시 가능.
- **수정안**: 안전망 실패 시 해당 예측을 보수적(고위험 쪽)으로 처리하거나 오류 표면화.

### H3. 파생변수 공식/방어 불일치
- **위치**: `derived.py:141-150` vs `predictor.py:296-300`
- **내용**: derived는 TG<400일 때만 Friedewald LDL 계산하지만 predictor는 TG≥400에도 적용(부정확). Cr≤0 방어 없음(0 division/음수 eGFR).
- **수정안**: LDL/eGFR/HOMA 계산을 `derived.py` 단일 함수로 통합, 입력 가드 추가.

### H4. dev 모드 무인증
- **위치**: `backend/main.py:41-43`
- **내용**: `REQUIRED_API_TOKEN` 없으면 `/api/*` 전체 무인증 통과. Tauri 배포본은 항상 토큰 주입(`lib.rs:190-199`)하므로 안전하지만, 직접 uvicorn 실행 시 개방.
- **수정안**: `DBCARE_DESKTOP=1`(배포) 일 때는 토큰 없으면 fail-closed.
